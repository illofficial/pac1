# Деплой бэкенда на Render

`Dockerfile` и `render.yaml` уже готовы (лежат в корне этого архива) - они
описывают весь деплой, тебе останется только нажать кнопки в интерфейсе
Render. Ключи/токены Render мне передавать не нужно ни на одном из шагов.

## Путь A - через GitHub (обычный способ, ключи не нужны никому)

1. Залей содержимое этой папки (`mastering-service/`) в свой репозиторий на
   GitHub - можно просто через GitHub Desktop/веб-загрузку файлов, если не
   пользуешься git в терминале.
2. В Render: New → Blueprint → выбрать этот репозиторий. Render сам найдёт
   `render.yaml` и предложит создать сервис `mastering-service` по нему.
3. Render попросит значение `APP_APPLE_ID` (единственная переменная с
   `sync: false`) - на старте можно оставить пустым или поставить
   заглушку, `subscriptions.py` требует её только при реальной
   production-проверке подписи. Впишешь настоящее значение, когда создашь
   приложение в App Store Connect (см. `ios-app/README.md`, шаг 4).
4. Deploy. Сборка займёт пару минут (Docker-образ с ffmpeg).
5. После деплоя Render выдаст адрес вида `https://mastering-service-xxxx.onrender.com`.
   Этот адрес:
   - вставь в `ios-app/MasteringApp/Config.swift` → `baseURL`;
   - используй, если захочешь открыть сайт напрямую в браузере для проверки.
6. Загрузи Apple root-сертификаты в `backend/certs/` (см.
   `backend/certs/README.md`) - без них `/api/subscription/verify` не
   заработает. Для Render это означает закоммитить файлы `.cer` в тот же
   репозиторий (они не секретные - это публичные сертификаты Apple).

## Путь B - если хочешь, чтобы код в GitHub залил я

Это возможно, но токен для этого должен быть **GitHub**, а не Render -
Render к моей среде всё равно недоступен. Если ты создашь **fine-grained
Personal Access Token** на github.com, ограниченный:
- только одним конкретным (новым, пустым) репозиторием,
- только правом Contents: Read and write,
- с коротким сроком действия (например, 1 день),

- и пришлёшь мне его — я запушу туда содержимое проекта, а дальше ты сам
подключаешь этот репозиторий в Render (шаги 2-6 выше) - это уже происходит
в самом Render через их встроенную OAuth-интеграцию с GitHub, без обмена
ключами со мной. Токен GitHub после этого стоит сразу отозвать в
настройках GitHub (Settings → Developer settings → Personal access
tokens).

## После деплоя - быстрая проверка

```bash
curl https://<твой-адрес>.onrender.com/api/subscription/status \
  -H "X-Device-Id: test"
# {"entitled": false, "max_duration_seconds": 180, "daily_limit": 1, "used_today": 0}
```

Если это отвечает - бэкенд живой и правильно раздаёт лимиты. Дальше можно
открыть `https://<твой-адрес>.onrender.com` в браузере и проверить сам
интерфейс, а затем прописать этот адрес в Xcode-проекте.

## На заметку про бесплатный тариф Render

Free/Starter-инстансы Render засыпают после периода бездействия и
"просыпаются" с задержкой на первый запрос - это нормально для прототипа,
но для реального использования (особенно из iOS-приложения, где холодный
старт будет ощущаться как зависшая обработка) стоит перейти на платный
план без автозасыпания.
